## 목표

나를 소개하는 웹사이트를 만들고, 코드를 고쳐서 `main`에 push하기만 하면
**사람이 손대지 않아도 자동으로 빌드되고 공개 주소에 반영되는** 구조를 갖추는 것이 목표였습니다.
화면이 예쁜 것보다, **어느 화면 크기와 어느 경로에서 열어도 깨지지 않고 실제로 동작하는 사이트**를 우선했습니다.

## 역할 나누기

개인 활동이며, AI 도구(Claude)와 함께 만들었습니다.

| 내가 한 일 | AI(Claude)가 한 일 |
|---|---|
| 테마 후보 중 **LoveIt** 선택 | 테마별 장단점과 지원 Hugo 버전 조사 |
| 홈 화면 구조를 직접 그려서 요청 (활동 카드 3열 + **⊕ 활동 추가** 버튼) | 템플릿과 스타일 코드 작성 |
| 디자인 방향 결정: 왼쪽 위 간판을 이름 대신 `Portfolio`로, 영어 소개 추가, 배경 시안 3개 중 **A안** 선택, 소개를 표로 정리 | 시안 제작과 적용 |
| 소개·활동 글에 들어갈 **실제 경험과 계획** 제공, 사실과 다른 문장 수정 | 문장 초안 작성 |
| 불편한 점 발견: 다크 모드 버튼을 두 번 눌러야 바뀜, 디자인이 심심함 | 원인 분석과 수정안 |
| 홈 배치 결정: 프로필을 **왼쪽 끝 세로 바**로 붙이고 활동 카드가 먼저 보이게 함, 빈 공간에 연락처·관심 분야 넣기 | 레이아웃 시안과 적용 |
| 기능 아이디어: 활동 목록 **미리보기**, **분야 필터**, 사이트 안에서 활동 추가·상태 변경·글 수정 | 구현 방법 비교(토큰 사용 여부 등)와 코드 작성 |
| 오류 발견: 미리보기 카드가 **겹쳐** 보임, 다크 모드 아이콘이 **설정 톱니**처럼 보임 | 원인 재현과 수정 |
| 여러 방법 중 **토큰 없이 GitHub 화면으로 넘기는 방식** 선택 | 방법별 장단점과 보안 위험 설명 |
| 배포 스크립트 실행, Git 초기화·원격 연결, **커밋과 push** | 빌드 검증, 오류 원인 분석 |

초기 설정 커밋 31개는 AI가 작성한 변경을 패치로 받아 적용했고, 그 뒤로는 바뀐 내용을 확인하고 직접 커밋했습니다.

## 만든 기능

| 기능 | 내용 | 관련 파일 |
|---|---|---|
| 활동 카드 홈 | 표지·상태·분야·기술 배지가 있는 카드. 화면 폭과 활동 개수에 맞춰 **열 수가 자동으로** 바뀜 | `site/layouts/home.html`, `site/layouts/_partials/activity-card.html` |
| 왼쪽 프로필 바 | 넓은 화면에서 프로필을 왼쪽 끝 세로 바로 고정. 이름을 누르면 소개 페이지로 이동, 이메일·관심 분야·써 본 기술·지금 하고 있는 것 표시 | `site/layouts/_partials/home/profile.html`, `site/hugo.toml` |
| 분야 필터 | 글에 `category`(예: 보안)를 적으면 홈에 필터 버튼이 자동으로 생기고, 누르면 그 분야 카드만 보임 | `site/layouts/home.html` |
| 활동 목록 미리보기 | 활동 페이지에서 제목에 마우스를 올리면 표지·상태·요약 카드가 뜸 | `site/layouts/posts/section.html` |
| ⊕ 활동 추가 | 사이트 안 입력 창에서 제목·날짜·상태·분야·기술·요약을 넣으면, 그 값이 채워진 GitHub 새 파일 화면이 열림 | `site/layouts/home.html`, `site/layouts/_partials/activity-new-template.html` |
| 상태 바꾸기 | 카드의 **완료로 / 진행 중으로** 버튼을 누르면 바꿀 줄을 복사하고 그 글의 GitHub 편집 화면을 엶 | `site/layouts/home.html` |
| 이 글 수정하기 | 활동 글 화면에서 원문을 불러와 고친 뒤, 복사해서 GitHub 편집 화면에 붙여 넣어 저장 | `site/layouts/posts/single.html` |
| 한국어 404 페이지 | 잘못된 주소에서 홈·활동·소개로 가는 버튼 제공 | `site/layouts/404.html` |
| 본문 바로가기 | 키보드 Tab을 처음 누르면 나타나 메뉴를 건너뜀 | `site/layouts/baseof.html` |
| 다크 모드 한 번에 전환 | 버튼을 누를 때마다 밝게 ↔ 어둡게 바로 바뀜. 밝을 때는 달, 어두울 때는 해 아이콘 | `site/layouts/baseof.html`, `site/assets/css/_custom.scss` |
| 홈 디자인 | `</> Portfolio` 간판, 영어 소개, 은은한 보라·분홍 빛 배경 | `site/hugo.toml`, `site/assets/css/_custom.scss` |
| 이미지 설명 | 모든 이미지의 대체 텍스트를 파일 경로 대신 설명 문장으로 | `site/layouts/_markup/render-image.html` 외 |

활동 추가·상태 바꾸기·글 수정 버튼은 주소 끝에 `?admin`을 붙인 브라우저에서만 보입니다. 다만 이건 **버튼을 숨기는 기능일 뿐**이고, 실제로 내용을 바꾸는 권한은 GitHub 계정에 있습니다.
다른 사람이 버튼을 켜고 눌러도 GitHub에서 **변경 제안(Pull Request)** 만 보낼 수 있고, 제가 직접 승인하지 않으면 사이트에 반영되지 않습니다. 사이트 코드에는 비밀번호나 토큰이 없습니다.

## 진행 과정

### 1. 테마 선택: LoveIt

후보로 **LoveIt**과 **Paper**를 비교했습니다.

- Paper는 가볍고 오류가 적지만, 블로그형이라 소개·활동 메뉴를 직접 만들어야 했습니다.
- LoveIt은 프로필형 홈과 한국어 언어 파일을 기본으로 갖추고 있어 소개 페이지 구성이 쉬웠습니다.

기능이 많은 만큼 점검할 곳도 많아지지만, **한국어 지원과 프로필 홈**이 이 사이트의 목적에 더 맞아 LoveIt을 골랐습니다.

### 2. 어떤 ZIP을 받을지 결정

처음에는 안정 버전인 릴리스(v0.3.1) ZIP을 받으려 했습니다.
그런데 수업에서 제공한 배포 스크립트를 읽어 보니 **Download ZIP(master)** 과 Hugo 0.167.0 조합으로 빌드를 검증하고 있었습니다.
v0.3.x는 Hugo 0.145까지만 지원해서 맞지 않았기 때문에 **master ZIP**으로 바꿨고, 배포 전에 같은 Hugo 버전으로 미리 빌드해 성공을 확인했습니다.

## 문제 해결 기록

| # | 문제 | 원인 | 해결 |
|:---:|---|---|---|
| 1 | 첫 push가 거부됨 | 테마 예제 설정에 제작자의 데모용 지도·검색 **API 키**가 남아 있음 | "허용하고 올리기" 대신 키를 지우고, 아직 올리지 않은 첫 커밋을 고쳐 씀 |
| 2 | 소개 페이지가 404 | 글 날짜를 현재보다 늦게 적어 Hugo가 **미래 글**로 보고 만들지 않음 | 날짜를 바로잡음 |
| 3 | 활동 카드에 표지가 안 보임 | 테마가 확장자 없는 이름으로 이미지를 찾음 | 글에 표지 파일 이름을 직접 지정 |
| 4 | 재배포 후 화면 일부가 깨짐 | 브라우저가 **옛 CSS를 캐시**에서 꺼내 새 HTML과 섞어 씀 | CSS 파일 이름에 내용 해시를 붙임 |
| 5 | 재배포 직후 스타일이 **전부** 빠짐 | 4번 수정 때문에, 캐시에 남은 옛 HTML이 지워진 옛 이름의 CSS를 요청해 404 | 파일 이름은 고정하고 주소 뒤에 `?v=해시`만 붙이는 방식으로 다시 수정 |
| 6 | InstaClone 활동 페이지가 404 | 글 파일(`index.md`)을 **커밋하지 않고** push함 | 커밋 후 재배포. push 전에 `git status`로 확인하는 습관을 들임 |
| 7 | 다크 모드 버튼을 두 번 눌러야 바뀜 | 버튼이 자동 → 밝게 → 어둡게 3단계를 돌아, 자동과 어둡게가 같아 보임 | 누를 때마다 지금 화면의 반대로 바로 바뀌게 함 |
| 8 | 로컬 빌드가 Dart Sass 없이도 되는 줄 알았음 | 이전 빌드의 **캐시**가 남아 있어 성공한 것처럼 보임 | 캐시를 지우고 다시 확인한 뒤 README에 필수 도구로 적음 |
| 9 | 활동 목록 미리보기 카드가 제목을 가림 | 카드가 제목과 같은 높이에 겹쳐 뜸 | 카드 위치를 제목 오른쪽 위로 옮김 |
| 10 | 미리보기 카드 두 개가 **겹쳐** 보임 | 키보드 초점이 있는 제목과 마우스를 올린 제목의 카드가 동시에 뜸 | 마우스를 올린 쪽만 보이도록 우선순위를 정함 |
| 11 | 다크 모드 버튼이 **설정(톱니)** 버튼처럼 보임 | 테마 기본 아이콘의 해 모양이 톱니와 비슷함 | 밝을 때는 달, 어두울 때는 동그란 해 아이콘으로 바꾸고, 버튼 이름도 "다크 모드로 전환"처럼 읽히게 함 |
| 12 | 화면이 조금만 좁아도 카드가 1열이 됨 | 카드 최소 폭을 크게 잡아 두 칸이 들어가지 못함 | 최소 폭을 줄이고 남는 공간에 맞춰 열 수를 자동으로 정하게 함 |
| 13 | 사이트 안에서 바로 저장하게 만들 수 있는지 | 정적 사이트라 저장하려면 GitHub 토큰이 필요하고, 토큰을 사이트에 넣으면 **누구나 볼 수 있음** | 토큰 없이 입력 내용을 GitHub 편집 화면으로 넘기는 방식을 택함. 저장은 저장소 주인만 가능 |
| 14 | 배포(Actions)가 실패함 | 로그를 보니 코드가 아니라 Hugo 설치 파일을 받는 GitHub 서버의 **504 오류** | 같은 파일로 로컬 빌드가 되는 것을 확인한 뒤 **Re-run failed jobs**로 다시 실행해 성공 |

## 결과

- 공개 주소: <https://yusinbin.github.io/1101NewProject1/>
- `main`에 push할 때마다 Actions가 자동으로 빌드·배포하고, 수정 내용이 공개 사이트에 반영되는 것을 확인했습니다.
- 배포된 화면에서 실패한 요청 0건, 깨진 이미지 0건, 모든 메뉴 링크가 저장소 하위 경로(`/1101NewProject1/`)로 올바르게 연결되는 것을 확인했습니다.
- 1440px·390px 화면에서 홈 카드 열 수가 화면 폭에 맞게 바뀌고 가로로 넘치지 않는 것을 확인했습니다.
- 분야 필터를 누르면 그 분야 카드만 남고, ⊕ 입력 창·상태 바꾸기·글 수정 창이 밝은·어두운 화면과 휴대폰 폭에서 정상으로 열리는 것을 확인했습니다.

## 배운 점과 다음 개선

**배운 점**

- **Actions가 초록색이어도 화면이 정상이라는 뜻은 아니었습니다.** 배포 후에는 반드시 실제 주소를 열어 확인해야 합니다.
- **고친 것이 새 문제를 만들 수 있었습니다.** 4번 수정이 5번 문제를 만든 것처럼, 수정한 뒤에도 다시 확인해야 합니다.
- 예제 파일에는 남의 키나 데모 설정처럼 그대로 올리면 안 되는 값이 숨어 있을 수 있습니다.
- **편리함과 보안은 같이 따져야 했습니다.** 사이트 안에서 바로 저장하는 게 가장 편하지만, 그러려면 비밀 값이 공개되어 한 단계 더 거치는 방식을 골랐습니다.
- 배포가 실패해도 먼저 **로그를 읽어** 내 코드 문제인지, 외부 서버 문제인지부터 구분해야 합니다.

**다음 단계**

- 아직 키보드만으로 조작하는 경우, 화면 확대, 창 크기를 바꿀 때의 동작은 충분히 점검하지 못했습니다. → 기능 검증표를 만들어 하나씩 확인합니다.
- 홈의 한국어 소개 문구가 타자 효과 스크립트로만 나타나, 스크립트가 늦거나 멈추면 보이지 않습니다. → 문구가 항상 보이도록 보완합니다.
