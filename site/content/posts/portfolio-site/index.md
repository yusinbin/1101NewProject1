## 목표

나를 소개하는 웹사이트를 만들고, 코드를 고쳐서 `main`에 push하기만 하면
**사람이 손대지 않아도 자동으로 빌드되고 공개 주소에 반영되는** 구조를 갖추는 것이 목표였습니다.
화면이 예쁜 것보다, 어느 화면 크기와 어느 경로에서 열어도 깨지지 않고 실제로 동작하는 사이트를 우선했습니다.

## 내가 한 일

개인 활동으로 다음을 직접 수행했습니다. AI 도구(Claude)는 설정 조사, 오류 원인 분석, 수정안 작성에 활용했고,
어떤 제안을 받아들일지와 최종 반영·확인은 제가 했습니다.

- 테마 후보 비교와 선택
- 배포 준비 스크립트 실행, Git 저장소 초기화와 원격 연결
- GitHub Pages 배포 설정과 Actions 결과 확인
- 테마 데모 콘텐츠 정리, 사이트 정보·메뉴·프로필을 본인 정보로 교체
- 배포된 화면에서 링크·이미지·언어 설정 점검

## 진행 과정

### 1. 테마 선택: LoveIt

후보로 **LoveIt**과 **Paper**를 비교했습니다.

- Paper는 가볍고 오류가 적지만, 블로그형이라 소개·활동 메뉴를 직접 만들어야 했습니다.
- LoveIt은 프로필형 홈과 한국어 언어 파일을 기본으로 갖추고 있어 소개 페이지 구성이 쉬웠습니다.

기능이 많은 만큼 점검할 곳도 많아지지만, **한국어 지원과 프로필 홈**이 이 사이트의 목적에 더 맞아 LoveIt을 골랐습니다.

### 2. 어떤 ZIP을 받을지 결정

처음에는 안정 버전인 릴리스(v0.3.1) ZIP을 받으려 했습니다.
그런데 수업에서 제공한 배포 스크립트를 읽어 보니, 저장소 첫 화면의 **Download ZIP(master)** 과
Hugo 0.167.0 조합으로 빌드를 검증하고 있었습니다. v0.3.x는 Hugo 0.145까지만 지원해서
스크립트가 쓰는 버전과 맞지 않았기 때문에 **master ZIP**으로 바꿨습니다.
배포 전에 같은 Hugo 버전으로 미리 빌드해 보고 성공하는 것을 확인한 뒤 진행했습니다.

### 3. 첫 push가 막힌 문제 해결

첫 push에서 GitHub가 **비밀 키가 포함되어 있다**며 업로드를 거부했습니다.

- **원인**: 테마 예제 설정(`hugo.toml`)에 테마 제작자가 데모용으로 넣어 둔 지도(Mapbox) 토큰과 검색(Algolia) 키가 남아 있었습니다.
- **판단**: GitHub가 제시한 "허용하고 올리기" 대신, 남의 키를 내 저장소에 올리지 않는 쪽을 택했습니다.
- **수정**: 키 값을 비우고, 아직 push되지 않은 첫 커밋을 고쳐 써서(`git commit --amend`) 기록에서도 제거했습니다.
- **확인**: 키를 비운 상태로 빌드가 성공하는지 확인한 뒤 다시 push해 배포까지 완료했습니다.

### 4. 데모 정리와 내 정보로 바꾸기

배포에 성공한 첫 화면은 테마 데모 그대로였습니다. 다음 항목을 하나씩 바꾸고 각각 커밋으로 남겼습니다.

- 사이트 제목·로고·작성자 → 빈유신
- 기본 언어 → 한국어(`lang="ko"`)
- 가짜 소셜 링크(`x.com/xxxx` 등) 12개 삭제, GitHub만 유지
- 예시 글 12편, 데모 이미지, 제작자의 댓글 서버 설정 삭제
- 홈 타자 효과가 끝나면 커서 깜빡임이 멈추도록 설정
- 이미지 대체 텍스트(alt)가 파일 경로로 나오던 문제를 고쳐 화면 낭독기가 내용을 읽을 수 있게 수정

## 배운 점과 다음 개선

**배운 점**

- Actions가 초록색으로 성공해도 화면이 정상이라는 뜻은 아니었습니다. 배포 후에는 반드시 실제 주소를 열어 확인해야 합니다.
- 예제 파일에는 남의 키나 데모 설정처럼 그대로 올리면 안 되는 값이 숨어 있을 수 있습니다.
- 글의 날짜를 현재 시각보다 늦게 적으면 Hugo가 "미래 글"로 보고 페이지를 만들지 않는다는 것도 직접 겪으며 알게 됐습니다.

**아쉬운 점과 다음 단계**

- 아직 키보드만으로 조작하는 경우와 태블릿 화면 크기는 충분히 점검하지 못했습니다. → 기능 검증표를 만들어 화면 폭별·키보드 조작을 하나씩 확인할 계획입니다.
- 저장소의 README가 아직 테마 설명 그대로입니다. → 설치·빌드·수정 방법을 담은 본인용 README로 바꿀 예정입니다.
